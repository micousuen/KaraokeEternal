Runtime Configuration Design

Karaoke Eternal · implementation status: current · updated 2026-08-13

System Architecture Design

This document is the design inventory for runtime configuration. It covers server startup, authentication, guest retention, media delivery, transcoding, background processing, WhisperX, vocal separation, audio-track classification, and maintenance.

Configuration rules

  • Environment variables are read when the owning module or process starts. Restart the server after changing them.
  • For options exposed by both CLI and environment, an explicit CLI option wins.
  • Invalid numeric values generally fall back to the documented default; a few bounded values are clamped as noted.
  • Durations ending in _MS use milliseconds. KES_SESSION_MAX_AGE_SECONDS uses seconds.
  • YAML processing configuration is validated strictly. Invalid values stop that configuration from loading.
  • Sensitive paths and provider URLs should be supplied through deployment secrets or environment files, not committed.
Existing cookies issued before expiring sessions were introduced do not contain an expiration claim and require one new sign-in.

Security and account lifecycle

VariableDefaultUnitDesign and operational effect
KES_SESSION_MAX_AGE_SECONDS604800seconds (7 days)Maximum signed-login lifetime. Every HTTP request and socket connection also revalidates the current user, role, account revision, and room, so deletion or authorization changes revoke a session immediately.
KES_LOGIN_MAX_CONCURRENT4operationsMaximum simultaneous password verification operations server-wide. Additional attempts receive HTTP 429, protecting CPU and memory from excessive Argon2 work.
KES_LOGIN_MAX_FAILURES5attemptsFailures allowed for one IP-address/username pair before backoff. The fifth failure establishes the first delay; a request made during that delay is rejected.
KES_LOGIN_FAILURE_WINDOW_MS90000015 minutesInactive failure records older than this window expire.
KES_LOGIN_BACKOFF_MS1000millisecondsInitial delay after reaching the failure threshold. Repeated failures double the delay. With the default, delays rise from 1 second to a maximum effective delay of 256 seconds and never exceed the five-minute safety ceiling.
KES_GUEST_RETENTION_DAYS7daysDeletes accounts whose current role is guest once their creation age crosses the cutoff. Promoted/registered users are not affected. Associated queue entries and stars are deleted, and remaining guest sockets are disconnected.
KES_GUEST_CLEANUP_INTERVAL_MS216000006 hoursFrequency of expired-guest checks. Cleanup also runs once at server startup, so actual removal occurs at startup or within one interval after the retention cutoff.
KES_ROTATE_KEYfalsebooleanRotates the JWT signing key at startup and invalidates all existing login cookies. Accepted true values are 1 and true.

Process and worker deadlines

VariableDefaultApplies toFailure behavior
KES_TRANSCODE_TIMEOUT_MS600000 (10 min)One browser-media FFmpeg artifactThe artifact fails and its partial file is removed.
KES_FFPROBE_TIMEOUT_MS30000 (30 sec)Codec, duration, and stream probesThe request or processing stage fails instead of holding a queue indefinitely.
KES_MEDIA_PROCESS_TIMEOUT_MS600000 (10 min)FFmpeg steps used by separation and scriptingThe active media-processing stage fails and temporary work is cleaned.
KES_SEPARATOR_TIMEOUT_MS1800000 (30 min)One audio-separator/Demucs invocationThe separation task fails and the queue advances.
KES_AUDIO_CLASSIFIER_TIMEOUT_MS120000 (2 min)Dual-audio vocal/instrumental classifier workerThe worker terminates; callers may fall back to physical track order.
KES_METADATA_TIMEOUT_MS120000 (2 min)Slow technical metadata workerThe worker terminates and the next background metadata job can run.
KES_WHISPERX_TIMEOUT_MS600000 (10 min)Each WhisperX worker request, including mount/transcribe commandsThe pending request fails; the worker can be restarted for later work.
KES_YOUTUBE_PROCESSING_TIMEOUT_MS3600000 (60 min)Maximum time a completed YouTube download waits for its script and instrumental track before it can enter the queue.The download remains in the library but is not queued, and the YouTube job reports an error.

Timed-out child processes receive SIGTERM, followed by SIGKILL after the process-runner grace period if they do not exit.

Operational guidance

  • Raise concurrency only after measuring CPU, memory, thermals, and playback startup latency.
  • Keep playback timeouts long enough for the largest supported media on the slowest deployed CPU.
  • Reducing guest retention removes guest queue history and stars sooner; converting a guest to a registered role preserves the account.
  • When exposed outside a trusted LAN, use HTTPS, keep login limits enabled, and place provider URLs and credentials in deployment secrets.
